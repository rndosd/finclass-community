# 검증과 공개 전 확인

이 소스 공개와 실제 학급 운영의 준비는 구분합니다. 독립 설치 항목은 각 운영자가 실제 운영 전에 확인할 사항입니다. 확인한 범위는 verification.md를 참고하세요.

## 공개 파일

- [x] 프로젝트의 비상업적 이용 LICENSE와 NOTICE 포함
- [x] 프로젝트 제작 그림 유지, 외부 로고·미확인 음원 대체 및 폰트 고지 보존
- [ ] 사용하는 외부 서비스·위젯 데이터의 조건 확인
- [ ] 이미지 내부의 이름·학생 기록, 텍스트의 정적 UID/학급 ID, 첨부파일·외부 파일 URL 수동 검토
- [ ] 실제 키·토큰·서비스 계정·학생 데이터·운영 로그·백업·과거 Git 이력 없는지 확인
- [ ] 원본 서비스/운영자에게 연결되는 주소·문의 버튼·법적 안내가 없는지 확인
- [ ] 실험·시안 경로와 서버 함수가 직접 URL로도 접근되지 않는지 확인

`.gitignore`는 이미 추적된 파일이나 과거 이력을 지워 주지 않습니다. 검토한 폴더만 새 저장소로
등록합니다. 원본 저장소의 공개 설정을 바꾸거나 폴더 전체를 `git add .`로 올리는 방식은 사용하지 않습니다.

## 독립 설치

- [ ] 깨끗한 컴퓨터/작업 폴더에서 `npm ci`와 `npm --prefix functions ci` 성공
- [ ] 실제 자기 설정으로 build 성공, 예시 설정 및 프로젝트 불일치에서는 시작 실패
- [ ] 원본 프로젝트 없이 새 Auth/Firestore/Storage/Functions/Hosting/R2만으로 동작
- [ ] 첫 관리자, 교사 가입/학급 생성, 가짜 학생 등록·로그인·비밀번호 변경 확인
- [ ] 학생이 다른 학급·관리자 기능·권한 없는 데이터에 접근하지 못하는지 확인
- [ ] 송금·급여·상점 구매·세금 납부·취소의 잔액과 로그 확인
- [ ] 같은 요청 재시도 시 이중 지급/차감이 생기지 않는지 확인
- [ ] 미션 제출·승인, 기부·기금·주식·부동산·경찰·의회 중 사용하려는 기능 시험
- [ ] R2/Storage 업로드·삭제·origin 제한과 App Check 토큰 확인
- [ ] 예약 작업과 외부 API 키 연결, 비용 알림, 백업·복구 확인
- [ ] 운영자 연락처·실제 개인정보처리방침·지원 범위·종료 공지 반영

금액과 권한은 빌드 성공만으로 검증되지 않습니다. 가짜 학생과 별도 개발 프로젝트에서 실제 결과를 확인합니다.
라이브 클라우드 점검은 운영자가 정확한 대상과 쓰기 범위를 정한 후 수행합니다.

## 포함된 확인 명령

`npm run test:core`는 설정 계약·권한 카탈로그·금액 요청 유틸리티를,
`npm run test:backend`는 유지된 서버 회귀 테스트를 실행합니다.
일부 에뮬레이터 테스트는 환경 변수와 별도 실행 환경이 없으면 skip됩니다.
skip을 권한 검사 통과로 해석하지 않습니다. 기존 규칙 파일은 유지하되
전체 새 설치에 대한 에뮬레이터 규칙 검증은 별도 완료해야 합니다.

원본의 CSP는 기존 운영 도메인을 포함한 report-only 정책이어서 초안 설정에서 제외했습니다.
다른 보안 헤더는 유지했습니다. 자기 Auth/Functions/R2/TradingView 도메인에 맞춘
CSP를 report-only로 검증하고 적용 여부를 정하세요. CSP 설정 완료로 표시하지 않습니다.
