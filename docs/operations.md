# 운영 안내

## 최초 운영자와 첫 학급

1. 자기 새 프로젝트의 Authentication에 별도 운영자 계정을 만듭니다. 기존 학생이나 학급 교사의
   역할을 관리자 역할로 덮어쓰지 않습니다. 콘솔에서 해당 계정의 UID를 확인합니다.
2. 이 프로젝트에만 필요한 권한을 가진 로컬 Application Default Credentials를 준비합니다.
   Google Cloud CLI를 사용하는 경우 `gcloud auth application-default login`으로 로그인합니다.
   Firebase CLI 로그인과 ADC는 서로 다릅니다. 서비스 계정 개인키를 공개 저장소에 넣지 않습니다.
3. 아래 명령으로 대상과 예정 변경을 확인합니다. 기본 동작은 읽기만 수행합니다.

```sh
npm run bootstrap:admin -- --project YOUR_PROJECT_ID --uid OPERATOR_AUTH_UID
```

4. 자기 프로젝트와 계정이 맞으면 본인이 직접 적용합니다.

```sh
npm run bootstrap:admin -- --project YOUR_PROJECT_ID --uid OPERATOR_AUTH_UID --apply
```

이 도구는 기존 Auth claims를 보존하면서 `role=admin`을 설정하고 `users/{uid}`의 관리자
프로필을 만듭니다. Firestore와 Auth는 하나의 원자적 트랜잭션이 아니므로 한쪽 실패 시 같은
명령을 재실행해 상태를 맞춥니다. 원본 서비스 프로젝트는 대상에서 차단합니다.
`addAdminRole` callable을 다시 열거나 보안 규칙을 완화해서 관리자 계정을 만들지 않습니다.

5. 로그아웃 후 다시 로그인해 새 claims를 받습니다. 자기 개인정보 안내를 작성한 뒤 동의를 완료합니다.
6. 별도 교사 계정으로 기존 교사 가입 화면을 이용해 자기 학급을 만듭니다.
   현재 가입 callable은 정상 가입 시 승인된 교사 프로필과 학급을 함께 생성합니다.
   남아 있는 관리자 승인 도구를 신규 가입마다 필수 절차라고 가정하지 않습니다.
7. 가짜 학생 2~3명으로 학생 생성·로그인, 권한과 거래를 먼저 시험합니다.

## 개인 운영의 범위

혼자 한 학급만 운영해도 Firebase Auth, Firestore, Functions, Storage/Hosting과 R2는 필요합니다.
첫 관리자를 만들기 위한 클라우드 소유자 권한과 수업 운영용 교사 권한은 분리해서 사용하세요.
FREE/PLUS/PRO/AI_PRO는 앱 내부 기능 정책입니다. 외부 결제나 원본 서비스 이용권과 자동 연결되지 않습니다.
`/admin/plans`와 `system/planConfig`의 기존 설정을 검토하고 실제로 사용할 기능을 설정합니다.
새 설치에서 기능 접근을 늘리더라도 서버의 역할·학급·거래 권한 검사까지 제거하지 않습니다.

## 비용과 정기 확인

Firestore 읽기·쓰기·저장량, Functions 호출/시간, 예약 작업, Cloud Tasks, 파일 트래픽,
외부 시세·AI 요청에서 비용이 발생할 수 있습니다. 비용이 0원이라고 약속하지 않습니다.
Firebase/GCP 예산 알림과 제공자 사용량을 확인하고, 학생 수가 늘기 전에 가짜 데이터로 사용량을 살펴보세요.
예약 작업은 학생이 접속하지 않아도 실행될 수 있습니다. Functions 목록에서 실제 배포된
scheduler·task를 함께 관리합니다.

## 데이터 보호와 백업

- 학생에게 필요한 최소 정보만 등록합니다. 실제 학생 정보가 담긴 스크린샷·로그를 공개 이슈에 올리지 않습니다.
- 자기 설치의 운영 주체, 처리 목적·항목, 보관·삭제 기준, 외부 전송과 문의 방법을 문서화합니다.
  기본 개인정보 페이지는 설치 초안이므로 실제 이용 전에 자기 방침으로 교체합니다.
- Firestore 백업/내보내기, Auth 계정 복구 절차, R2·Storage 객체 백업과 서버 설정 복구를 함께 준비합니다.
  코드만 보관하는 것은 데이터 백업이 아닙니다.
- 백업 파일과 비밀키는 접근이 제한된 장소에 따로 보관하고 가짜 데이터로 복원 연습을 합니다.
- 복구/정정할 때 거래 기록·감사 로그·연결된 원장을 보존합니다. 금액을 임의로 덮어쓰지 않습니다.

## 업데이트·장애·운영 종료

새 버전은 별도 개발 프로젝트에서 검사한 뒤 적용합니다. 배포 전 백업과 되돌릴 빌드를 확보합니다.
중복 요청, 실패 후 재시도와 거래 취소를 실제 상태로 확인합니다.
계정 삭제나 학급 초기화는 기존 서버 도구를 사용하고 화면에서 선택한 범위를 재확인합니다.

개인 설치를 종료할 때에는 이용자에게 일정과 자기 자료를 가져갈 방법을 안내하고,
보관 기준에 따라 데이터를 정리합니다. 예약 작업·호스팅·외부 API 키·버킷 접근도 함께 점검합니다.
원본 서비스의 종료일과 개인 설치본의 종료일은 별개입니다.
